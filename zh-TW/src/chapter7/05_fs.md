# fs：讀寫檔案與 scope

## 本集目標

學會用 `writeTextFile` 和 `readTextFile` 讀寫 App 自己的資料夾，分清楚 permission（能用哪個函式）與 scope（能碰哪些路徑），並知道寫檔前資料夾可能還不存在。

## 正文

### 範例：存檔、讀檔

fs plugin 的函式可以收完整路徑，也可以搭配 `baseDir`，寫成「相對於某個資料夾」的路徑。這一集用 `BaseDirectory.AppData`：作業系統替每個 App 準備的資料夾，專門放 App 自己的資料。`writeTextFile("note.txt", 內容, { baseDir: BaseDirectory.AppData })` 就是在那個資料夾裡寫 `note.txt`。資料夾實際在哪裡，下一集再說。

先裝 plugin：

```bash
npm run tauri add fs
```

它會在 `lib.rs` 註冊 plugin，並在 `capabilities/default.json` 的 `permissions` 加上 `fs:default`。頁面有兩個按鈕：「存檔」把一行字寫進 App 資料夾再讀回來，「存到桌面」故意寫到別的地方，等一下用來看 scope：

`index.html`：

```html
<!doctype html>
<html lang="zh-TW">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>fs</title>
    <link rel="stylesheet" href="/src/styles.css" />
    <script type="module" src="/src/main.ts" defer></script>
  </head>

  <body>
    <main class="container">
      <h1>fs</h1>
      <div class="row">
        <button id="save-btn" type="button">存檔</button>
        <button id="desktop-btn" type="button">存到桌面</button>
      </div>
      <p id="msg"></p>
    </main>
  </body>
</html>
```

`src/main.ts`：

```ts
import {
  BaseDirectory,
  mkdir,
  readTextFile,
  writeTextFile,
} from "@tauri-apps/plugin-fs";

const msgEl: HTMLElement | null = document.querySelector("#msg");
if (!msgEl) {
  throw new Error("找不到 #msg");
}

const report = async (action: () => Promise<string>) => {
  try {
    msgEl.textContent = await action();
  } catch (error) {
    msgEl.textContent = `出錯了：${error}`;
  }
};

document.querySelector("#save-btn")?.addEventListener("click", () =>
  report(async () => {
    await mkdir("", { baseDir: BaseDirectory.AppData, recursive: true });
    await writeTextFile("note.txt", "你好，fs", {
      baseDir: BaseDirectory.AppData,
    });
    const text = await readTextFile("note.txt", {
      baseDir: BaseDirectory.AppData,
    });
    return `存好了，讀回來是：${text}`;
  }),
);

document.querySelector("#desktop-btn")?.addEventListener("click", () =>
  report(async () => {
    await writeTextFile("note.txt", "你好，fs", {
      baseDir: BaseDirectory.Desktop,
    });
    return "存到桌面了";
  }),
);
```

`npm run tauri dev` 的輸出（節錄）：

```text
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 1.66s
     Running `target/debug/tauri-app`
```

按「存檔」，被擋下來了（permission 清單很長，這裡節錄）：

```text
出錯了：fs.write_text_file not allowed. Permissions associated with this command: fs:allow-app-write, fs:allow-app-write-recursive, fs:allow-appcache-write, …, fs:allow-write-text-file, fs:write-all, fs:write-files
```

`fs:default` 只放行「讀」：讀取 App 的專屬資料夾，以及建立這些資料夾。寫檔要另外放行。

### 放行寫入，以及 scope

在清單裡挑 `fs:allow-appdata-write-recursive`。這個名字是兩件事的組合，permission 與 scope 在這裡分得很清楚：

- permission 決定能用哪個函式：它包含所有寫入的函式（`writeTextFile`、`remove`、`rename`⋯⋯）。
- scope 決定能碰哪些路徑：它只涵蓋 `$APPDATA` 和底下的所有東西，也就是 `BaseDirectory.AppData` 指的資料夾。

`src-tauri/capabilities/default.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "opener:default",
    "fs:default",
    "fs:allow-appdata-write-recursive"
  ]
}
```

改完存檔，`tauri dev` 會自動重新編譯。再按「存檔」，顯示「存好了，讀回來是：你好，fs」。按「存到桌面」，函式放行了，可是桌面不在 scope 內，錯誤訊息跟剛才不同：

```text
出錯了：forbidden path: /Users/me/Desktop/note.txt, maybe it is not allowed on the scope for `allow-write-text-file` permission in your capability file
```

`not allowed` 是缺 permission，`forbidden path` 是路徑不在 scope 內，跟第 3 集 opener 的 `Not allowed to open path` 是同一層檢查。兩層都過，函式才會執行。所以光有函式的 permission 不夠：沒有任何 scope 時，單獨放行 `fs:allow-write-text-file`，寫 App 資料夾一樣是 `forbidden path`（`fs:default` 自帶 App 資料夾的 scope，搭配它才寫得進去）。

### 資料夾可能還不存在

存檔時先呼叫 `mkdir("", { baseDir: BaseDirectory.AppData, recursive: true })`。空字串表示 `AppData` 資料夾本身，`recursive: true` 表示已經存在也不會出錯。`mkdir` 不用另外放行，`fs:default` 已經包含了。這一行不能省，App 的資料夾不會自己出現，沒建的話，第一次寫入會得到 `failed to open file at path: … with error: No such file or directory (os error 2)`。

## 重點整理

- `baseDir: BaseDirectory.AppData` 讓路徑相對於 App 專屬的資料夾；`writeTextFile` 與 `readTextFile` 都要 `await`。
- `fs:default` 放行讀取與建立 App 的專屬資料夾；寫入要另外加，例如 `fs:allow-appdata-write-recursive`。
- permission 決定能用哪個函式，scope 決定能碰哪些路徑。`not allowed` 是缺 permission，`forbidden path` 是路徑不在 scope 內。
- 寫入前資料夾可能還不存在，先 `mkdir(..., { recursive: true })`。
