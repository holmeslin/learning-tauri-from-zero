# fs：讀寫檔案與 scope

## 本集目標

學會用 `writeTextFile` 和 `readTextFile` 讀寫 App 資料夾，分清楚 permission（能用哪個函式）與 scope（能碰哪些路徑），並知道寫檔前資料夾可能還不存在。

## 正文

### 範例：存檔、讀檔

fs plugin 的函式可以收完整路徑，也可以搭配 `baseDir`，寫成「相對於某個資料夾」的路徑。這一集用 `BaseDirectory.AppData`：作業系統替每個 App 準備的資料夾，專門放 App 自己的資料。`writeTextFile("note.txt", 內容, { baseDir: BaseDirectory.AppData })` 就是在那個資料夾裡寫 `note.txt`。資料夾實際在哪裡，下一集再說。

先照第 1 集的方式裝 plugin：

```bash
npm run tauri add fs
```

它會在 `lib.rs` 註冊 plugin，並在 `capabilities/default.json` 加上 `fs:default`：

`src-tauri/src/lib.rs`：

```rust
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
        .plugin(tauri_plugin_opener::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

`src-tauri/capabilities/default.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "opener:default",
    "fs:default"
  ]
}
```

頁面只有一個按鈕，把一行字寫進 App 資料夾，再讀回來：

`index.html`：

```html
<!doctype html>
<html lang="zh-TW">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>fs</title>
    <link rel="stylesheet" href="/src/styles.css" />
    <script type="module" src="/src/main.ts" defer></script>
  </head>

  <body>
    <main class="container">
      <h1>fs</h1>
      <div class="row">
        <button id="save-btn" type="button">存檔</button>
      </div>
      <p id="msg"></p>
    </main>
  </body>
</html>
```

`src/main.ts`：

```ts
import {
  BaseDirectory,
  mkdir,
  readTextFile,
  writeTextFile,
} from "@tauri-apps/plugin-fs";

const msgEl: HTMLElement | null = document.querySelector("#msg");
if (!msgEl) {
  throw new Error("找不到 #msg");
}

document.querySelector("#save-btn")?.addEventListener("click", async () => {
  try {
    await mkdir("", { baseDir: BaseDirectory.AppData, recursive: true });
    await writeTextFile("note.txt", "你好，fs", {
      baseDir: BaseDirectory.AppData,
    });
    const text = await readTextFile("note.txt", {
      baseDir: BaseDirectory.AppData,
    });
    msgEl.textContent = `存好了，讀回來是：${text}`;
  } catch (error) {
    msgEl.textContent = `出錯了：${error}`;
  }
});
```

執行 `npm run tauri dev`，按「存檔」，被擋下來了（permission 清單很長，這裡節錄）：

```text
出錯了：fs.write_text_file not allowed. Permissions associated with this command: fs:allow-app-write, fs:allow-app-write-recursive, fs:allow-appcache-write, …, fs:allow-write-text-file, fs:write-all, fs:write-files
```

### 放行寫入，以及 scope

`fs:default` 只放行讀取和建立 App 資料夾（所以 `mkdir` 沒被擋），寫檔要另外放行。在清單裡挑 `fs:allow-appdata-write-recursive`。這個名字包含兩件事。permission 決定能用哪些函式，這裡是所有寫入的函式（`writeTextFile`、`remove`、`rename`⋯⋯）。scope 決定能碰哪些路徑，這裡只涵蓋 `$APPDATA` 和底下的所有東西，也就是 `BaseDirectory.AppData` 指的資料夾。

`src-tauri/capabilities/default.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "core:default",
    "opener:default",
    "fs:default",
    "fs:allow-appdata-write-recursive"
  ]
}
```

改完存檔，`tauri dev` 會自動重新編譯。再按「存檔」，顯示「存好了，讀回來是：你好，fs」。再來看路徑不在 scope 內的情況。把 `writeTextFile` 那一行的 `BaseDirectory.AppData` 換成 `BaseDirectory.Desktop`，再按「存檔」。函式放行了，可是桌面不在 scope 內，錯誤訊息跟剛才不同：

```text
出錯了：forbidden path: /Users/me/Desktop/note.txt, maybe it is not allowed on the scope for `allow-write-text-file` permission in your capability file
```

`not allowed` 是缺 permission，`forbidden path` 是路徑不在 scope 內，兩關都過，函式才會執行。這麼長的說明只有開發模式才有，正式版只會顯示 `forbidden path: /Users/me/Desktop/note.txt`。另外，經由 dialog 的 `open()`、`save()` 選出來的路徑，plugin 會自動加進 fs 的 scope。所以讀使用者自己挑的檔案，不用另外設定 scope，函式的 permission 還是要放行。

範例裡寫檔之前的 `mkdir("", { baseDir: BaseDirectory.AppData, recursive: true })` 不能省：App 資料夾不會自己出現，沒建的話，第一次寫入會得到 `failed to open file at path: … with error: No such file or directory (os error 2)`。空字串表示 `AppData` 資料夾本身，`recursive: true` 表示已經存在也不會出錯。`mkdir` 不用另外放行，`fs:default` 已經包含了。

## 重點整理

- `baseDir: BaseDirectory.AppData` 讓路徑相對於 App 專屬的資料夾；`writeTextFile` 與 `readTextFile` 都要 `await`。
- `fs:default` 放行讀取與建立 App 資料夾；寫入要另外加，例如 `fs:allow-appdata-write-recursive`。
- permission 決定能用哪個函式，scope 決定能碰哪些路徑。`not allowed` 是缺 permission，`forbidden path` 是路徑不在 scope 內；經由 dialog 選出來的路徑會自動進 scope。
- 寫入前資料夾可能還不存在，先 `mkdir(..., { recursive: true })`。
