# 替自己的 command 定義 permission

## 本集目標

讓自己寫的 command 也要被 capability 放行才能呼叫，並用 scope 限制它的參數，檢查由 command 自己做。

## 正文

### 把缺口補起來

第 1 集看到的缺口是：plugin 與 core 的 command 沒被放行就不能呼叫，自己寫的 command 卻誰都能呼叫（第 3 章第 1 集也提過）。開關是：App 只要有任何一項自己的 permission，Tauri 就會檢查 App 的每一個 command，它們從此跟 plugin 的 command 一樣，要被放行才呼叫得到。最直接的做法是在 `build.rs` 列出 command，讓 Tauri 替它們產生 permission。

這集分三步：先讓 command 要被放行（`build.rs`），再讓 command 拿到 scope（`CommandScope`），最後把 command 與 scope 寫成一項 permission（`permissions/*.toml`）。

這集的例子是 `write_note`：前端給檔名和內容，Rust 在 App 資料夾裡寫檔，是第 12 章那兩個檔案 command 的縮小版。

`src-tauri/src/lib.rs`：

```rust
use std::path::{Component, Path};

use serde::Deserialize;
use tauri::ipc::{CommandScope, ScopeObjectMatch};
use tauri::{AppHandle, Manager};

#[derive(Debug, Deserialize)]
struct DirScope {
    dir: String,
}

impl ScopeObjectMatch for DirScope {
    type Input = Path;

    fn matches(&self, input: &Path) -> bool {
        input.starts_with(&self.dir)
    }
}

#[tauri::command]
fn write_note(
    app: AppHandle,
    name: String,
    text: String,
    scope: CommandScope<DirScope>,
) -> Result<String, String> {
    let relative = Path::new(&name);
    if !relative
        .components()
        .all(|part| matches!(part, Component::Normal(_)))
    {
        return Err(format!("路徑不合法：{name}"));
    }
    if scope.allows().is_empty() {
        return Err("這個 command 沒有設定 scope".to_string());
    }
    if !scope.matches(relative) {
        return Err(format!("不在 scope 內：{name}"));
    }
    let path = app
        .path()
        .app_data_dir()
        .map_err(|e| e.to_string())?
        .join(relative);
    if let Some(dir) = path.parent() {
        std::fs::create_dir_all(dir).map_err(|e| e.to_string())?;
    }
    std::fs::write(&path, text).map_err(|e| e.to_string())?;
    Ok(path.display().to_string())
}

#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .invoke_handler(tauri::generate_handler![write_note])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

`write_note` 依序做三件事：檢查路徑、檢查 scope、寫檔。前兩件是這集的重點，先照抄，後面一一說明。頁面沿用範本的表單，輸入框填檔名：

`src/main.ts`：

```ts
import { invoke } from "@tauri-apps/api/core";

const nameEl: HTMLInputElement | null = document.querySelector("#greet-input");
const msgEl: HTMLElement | null = document.querySelector("#greet-msg");
if (!nameEl || !msgEl) {
  throw new Error("找不到 #greet-input 或 #greet-msg");
}

document.querySelector("#greet-form")?.addEventListener("submit", async (event) => {
  event.preventDefault();
  try {
    const path = await invoke<string>("write_note", {
      name: nameEl.value,
      text: "你好，permission",
    });
```

### 在 `build.rs` 列出 command

範本的 `build.rs` 只有一行 `tauri_build::build()`。要告訴 Tauri 有哪些 command，改用 `try_build`，用 `AppManifest::commands` 列出名字：

`src-tauri/build.rs`：

```rust
fn main() {
    tauri_build::try_build(
        tauri_build::Attributes::new()
            .app_manifest(tauri_build::AppManifest::new().commands(&["write_note"])),
    )
    .expect("failed to run tauri-build");
}
```

建置時，Tauri 替列出的每個 command 產生兩項 permission，寫在 `src-tauri/permissions/autogenerated/` 底下：`allow-write-note` 放行它，`deny-write-note` 禁止它。名字是 command 名稱把底線換成連字號。App 自己的 permission 在 capability 裡不加前綴，不像 plugin 的有 `fs:`。

`capabilities/default.json` 沒動，還是範本的樣子，沒有放行 `write_note`：

`npm run tauri dev` 的輸出（節錄）：

```text
   Compiling tauri-app v0.1.0 (~/tauri-app/src-tauri)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 6.15s
     Running `target/debug/tauri-app`
```

輸入 `notes/a.txt` 按按鈕，`write_note` 被擋下來，訊息跟第 7 章第 2 集的格式一樣：

```text
出錯了：write_note not allowed. Permissions associated with this command: allow-write-note
```

從現在起，App 的 command 都要列進 `commands`，沒列的，不管有沒有放進 `generate_handler!`，前端一律呼叫不到。我們試過：把範本的 `greet` 放回 `generate_handler![greet, write_note]`，`build.rs` 仍只列 `write_note`，在頁面呼叫 `invoke("greet", { name: "x" })`。Promise 被拒絕，錯誤訊息是：

```text
greet not allowed. Command not found
```

不放進 `generate_handler!` 也是同一句。這是前端的 Promise 收到的錯誤，不是 `tauri dev` 的輸出，終端機沒有這則訊息。想自己看，在開發者工具的 Console 呼叫 `window.__TAURI__.core.invoke("greet", { name: "x" })` 就行（範本的 `withGlobalTauri` 是 `true`）。`write_note` 與 `greet` 這兩則都是開發模式的訊息，打包版只有 `Command write_note not allowed by ACL` 這種。

### scope 由 command 自己檢查

把 `allow-write-note` 放進 capability，`write_note` 就呼叫得到了，但它會回「這個 command 沒有設定 scope」，這是 `write_note` 自己回的，不是 Tauri 擋的。`allow-write-note` 只有 command、沒有 scope。第 3 集看到 fs plugin 遇到這種情況一律擋下，那是 fs plugin 自己的決定。

Tauri 對 scope 做的事只有一件：把 capability 與 permission 裡寫的 `allow`、`deny` 收集起來，從 `CommandScope<T>` 參數交給 command。`T` 是你自己定義的型別，能用 serde 讀就行，這裡的 `DirScope` 對應 scope 裡每一項 `{ "dir": "notes" }`。要怎麼比對，完全由 command 決定。

`CommandScope<T>` 只有掛在這個 command 的 permission 上的 scope。沒有 command 的 permission 帶的是全域 scope（第 3 集），要用另一個參數 `GlobalScope<T>` 另外取。第 3 集的「兩種 scope 加在一起」是 fs plugin 的做法，它兩個都取，自己合併，Tauri 不會替你合併。我們試過：另外寫一項只有 `dir = "global"`、沒有 command 的 permission，一起放進 capability，`write_note` 同時收 `CommandScope` 與 `GlobalScope`：`GlobalScope` 有那一筆，`CommandScope` 沒有，`global/x.txt` 照樣被 `scope.matches` 拒絕。自己的 command 想要兩種都算，就得兩個參數都取、自己合併。

這集的做法是實作 `ScopeObjectMatch`：`DirScope` 說明「輸入的路徑在不在我這個資料夾底下」，`scope.matches(路徑)` 就會做完整的判斷：路徑不能符合任何一項 `deny`，而且要符合某一項 `allow`。有兩個地方要自己補：

- `allow` 清單是空的時候，`matches` 回傳 `true`。沒設定 scope 就等於什麼都放行，所以 `write_note` 先檢查 `scope.allows().is_empty()`，空的就拒絕，預設不放行。
- scope 比對的只是路徑的字面。`notes/../secret/c.txt` 的開頭就是 `notes`，直接比對會通過。所以先檢查每一段都是普通的名字（`Component::Normal`），擋掉 `..`、開頭的 `/` 這類寫法。

### 把 scope 寫進 permission 檔

現在補上 scope。在 `src-tauri/permissions/` 底下放一個 `.toml` 檔，定義自己的 permission。（這個資料夾只要有 permission 檔，就算 `build.rs` 沒列任何 command，也會打開開頭說的開關。）

`src-tauri/permissions/notes.toml`：

```toml
[[permission]]
identifier = "write-notes"
description = "允許 write_note 寫入 notes 資料夾，但不含 notes/private"
commands.allow = ["write_note"]

[[permission.scope.allow]]
dir = "notes"

[[permission.scope.deny]]
dir = "notes/private"
```

一個 `[[permission]]` 就是第 3 集拆解過的結構：`identifier` 是名字，`commands.allow` 放行 `write_note`，`[[permission.scope.allow]]` 與 `[[permission.scope.deny]]` 各寫一項 scope。`dir` 這個欄位名稱是我們在 `DirScope` 自己取的。把 command 和 scope 綁在同一項 permission，capability 就只要引用名字。這個 App 也沒有用 opener，所以順手把 `opener:default` 拿掉：

`src-tauri/capabilities/default.json`：

```json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "主視窗",
  "windows": ["main"],
  "permissions": ["core:default", "write-notes"]
}
```

`npm run tauri dev` 的輸出（改了 `capabilities/default.json`、新增 `permissions/notes.toml` 之後）：

```text
        Info File src-tauri/capabilities/default.json changed. Rebuilding application...
     Running DevCommand (`cargo  run --no-default-features --color always --`)
   Compiling tauri-app v0.1.0 (~/tauri-app/src-tauri)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 2.88s
     Running `target/debug/tauri-app`
```

依序輸入四個檔名：

- `notes/a.txt`：「寫好了：/Users/me/Library/Application Support/tw.example.tauri-app/notes/a.txt」。
- `notes/private/b.txt`：「出錯了：不在 scope 內：notes/private/b.txt」，`deny` 優先。
- `secret/c.txt`：「出錯了：不在 scope 內：secret/c.txt」，沒有任何 `allow` 比對到。
- `../x.txt`：「出錯了：路徑不合法：../x.txt」，路徑那一關就擋下了。

### 回到第 12 章

第 12 章的 `read_file`、`write_file` 吃任何路徑（第 12 章第 1 集），也該收緊，但沒辦法像這集一樣限定一個資料夾：路徑是使用者用對話框挑的，或作業系統雙擊檔案時交來的，位置不固定。

第一個想到的是限制副檔名：scope 的每一項寫 `{ "ext": "md" }`，`matches` 改成比對 `Path::extension`。這擋不了多少。任何位置的 `*.md` 都過關；`x.md` 如果是指向私鑰的符號連結（symlink），`read_to_string` 會跟著連過去；`.MD` 算不算，也得自己決定。副檔名是命名習慣，不是信任界線。

比較對的方向是反過來：Rust 端只收「對話框或作業系統交來的路徑」。對話框由 Rust 端自己彈出來（dialog plugin 在 Rust 端也有選檔案的 API），選到的路徑、啟動參數與 `Opened` 交來的路徑（第 12 章第 7 集），都先記在 Rust 端的狀態裡；`read_file`、`write_file` 只認記下來的，前端不能自己編一個路徑。這樣就算前端被別人控制，也只能碰使用者真的選過、交給 App 的檔案。這要改的地方不少，本書沒有改第 12 章的程式，留給你當練習。

## 重點整理

- 自己的 command 預設不受 ACL 管；App 一有自己的 permission，所有 command 都要被放行才能呼叫。`build.rs` 的 `AppManifest::commands` 會替列出的 command 產生 `allow-<command>` 與 `deny-<command>`，沒列的就沒有 permission 可放行。
- App 自己的 permission 在 capability 裡不加前綴；用 `permissions/*.toml` 的 `[[permission]]` 可以把 command 與 scope 綁成一項。
- Tauri 只負責把 scope 交給 command（`CommandScope<T>`；全域 scope 要用 `GlobalScope<T>` 另外取，不會自動合併），比對由你寫。`allow` 為空時 `matches` 是 `true`，要自己先擋，路徑也要先清乾淨。
